# 서울세미텍 시스템

구매 · 품질 · 개발 · 생산 · 물류의 업무 흐름을 한 곳에서 입력하고 확인하는 사내 웹앱입니다.

- **운영 배포**: Codex Sites의 Cloudflare Workers + D1(DB) + R2(사진)를 사용합니다.
- **외부 패키지 없음**: 로컬 개발·테스트는 Node.js 22.13 이상과 내장 `node:sqlite`를 사용합니다.
- 로컬 데이터는 `data/app.db`와 `data/uploads/`, 운영 데이터는 영구 D1/R2에 저장됩니다.

## 실행

```bash
cd work-process-app
INVITE_CODE=local-test-code npm start  # http://localhost:3000
```

| 환경변수 | 기본값 | 설명 |
|---|---|---|
| `PORT` | `3000` | 서버 포트 |
| `DATA_DIR` | `./data` | DB·사진 저장 위치 (서버를 옮길 때 이 폴더만 백업) |
| `INVITE_CODE` | 없음 | **최초 가입 시** 초기 초대코드. 운영은 Sites 비밀 환경변수로 설정. 이후에는 관리자 화면에서 변경 |

테스트: `npm test`

## 가입 / 권한

- 가입: **이름 / 비밀번호 / 초대코드** (설정한 초대코드 사용)
- **처음 가입한 사람이 관리자**가 됩니다. 관리자는 `관리자 설정`에서
  - 초대코드 변경
  - 사용자별 담당 권한 지정: 구매 · 품질 · 개발(연구소) · 생산 · 물류, 관리자 지정
  - 비밀번호 초기화, 사용자 삭제

| 권한 | 할 수 있는 일 |
|---|---|
| 누구나 | 모든 목록 조회, 발주/세탁/일정/출하 입력, 분석·개발·샘플 **의뢰**, 발주입고 체크 |
| 품질 | 분석의뢰 승인·반려, 분석리스트 상태(대기/진행/완료) 변경 |
| 개발(연구소) | 개발의뢰 승인·반려, 개발리스트 상태 변경 |
| 생산 | 샘플의뢰 승인·반려, 샘플리스트 상태 변경, 다른 사람 생산일정 수정 |
| 구매 / 물류 | 다른 사람이 등록한 발주·세탁 / 출하 기록 수정·삭제 |
| 관리자 | 모든 권한 |

## 메뉴와 업무 흐름

| 부서 | 메뉴 | 내용 |
|---|---|---|
| 구매 | 발주목록 | 구매의뢰번호, 거래처, 품목명, 수량, 납기일. 물류 입고 상태가 색으로 표시됨 |
| 구매 | 세탁관리 | 입고일, (입고수량), 폐기수량, 불량폐기 사진 여러 장. 월별 폐기 합계·폐기율 |
| 품질 | 분석의뢰 | 의뢰요청서 ② 품질분석 양식. 접수대기 → 품질담당자 승인 시 접수번호 `Q-yymmdd-NN` 발급 |
| 품질 | 분석리스트 | 수입검사/의뢰검사/출하검사/공정검사 필터, 대기·진행·완료, 의뢰자 표시 |
| 개발 | 개발의뢰 | 타겟제품, 타겟단가, 사용용도, 사용량 등. 연구소담당자 승인 → `D-yymmdd-NN` |
| 개발 | 개발리스트 | 타겟제품, 타겟단가, 의뢰자, 대기·진행·완료 |
| 생산 | 샘플의뢰 / 샘플리스트 | 생산담당자 승인 → `S-yymmdd-NN`, 대기·진행·완료 |
| 생산 | 완제품 / 반제품 생산일정 | 일간·주간·월간 일정 입력(제품명, 수량), 일/주/월 달력 보기, 완료 체크 |
| 물류 | 입고목록 → 발주입고 | 발주목록에서 체크 → **입고확인(초록)** / **수량상이(빨강, 실입고 수량 입력)** / **확인중(노랑)** |
| 물류 | 출하목록 | 출고일, 품목명, 수량, 거래처. 기본은 오늘 날짜, 기간 조회 가능 |

의뢰서는 상세 화면에서 **인쇄**할 수 있습니다.

## 배포

**[Codex Sites 배포·백업 안내](DEPLOY.md)**를 따릅니다.
운영은 D1과 R2를 사용하므로 Railway나 `/data` 볼륨을 설정할 필요가 없습니다.
관리자 설정에서 업무 기록과 사진을 포함한 전체 백업을 다운로드할 수 있습니다.

검증: `npm test` / 배포 산출물: `npm run build`.
로컬 테스트는 Worker 로직을 SQLite/R2 호환 어댑터로 실행하며 실제 Cloudflare 런타임 검증을 대체하지는 않습니다.

## 구매·물류 추가 항목

- 구매 발주: COA 요청 체크와 제품·상품·원자재·부자재 분류. 입고목록에서도 확인할 수 있습니다.
- 물류 기타입고: 발주 없는 입고를 분류별로 등록·조회·수정·삭제합니다.
- 물류 출하: LOT를 등록·수정하고 목록에서 확인합니다.
- 기타입고 수정·삭제는 등록자, 물류 담당자 또는 관리자에게 허용됩니다.

회사 로고는 [서울세미텍 공식 홈페이지](https://seoulsemi.com)에서 가져온 원본을 사용합니다.

## 입고와 분석리스트 연동

- **입고목록 → 발주입고 → 입고확인**: 분석리스트에 수입검사(대기)를 자동 등록합니다.
- **기타입고 등록**: 등록 즉시 분석리스트에 수입검사(대기)를 자동 등록합니다.
- 품목명·입고처·분류·입고수량·입고일·COA 요청 여부를 함께 넘기고 Q 접수번호를 발급합니다.
- 같은 입고의 반복 확인은 중복 등록하지 않으며 기존 분석의 진행/완료 상태와 결과를 유지합니다.
- 원본 입고를 나중에 수정·삭제해도 분석 이력은 최초 등록 스냅샷으로 남습니다.
- 품질 담당자가 분석 상태와 결과를 관리합니다. 기존 수동 의뢰는 승인 절차를 그대로 따릅니다.

## BOM으로 생산일정 등록

1. 관리자 계정으로 **관리 → BOM 관리 → 새 BOM 등록**을 엽니다.
2. 제품명·제품코드·완제품/반제품 구분·기준 생산수량·생산 단위를 입력합니다.
3. 자재별 이름·분류·기준수량당 사용량·단위를 추가하고 저장합니다.
   예: 제품 100EA 기준 원단 5kg이면, 생산 300EA의 원단 소요량은 15kg입니다.
4. **생산 → 완제품/반제품 생산일정 → BOM에서 가져오기**를 선택하고 생산수량을 입력합니다.
5. 소요량을 확인해 일정을 저장합니다. 일정의 **BOM·소요량** 버튼에서 등록 당시 기준을 볼 수 있습니다.

BOM 수정이나 사용 중지는 기존 생산일정의 제품·자재 기준을 바꾸지 않습니다.

## 사진 첨부와 입출고 이상 여부

- 개발·샘플 의뢰: 작성 화면에서 사진을 선택하고, 상세의 **사진 보기·첨부**에서 추가/유지/삭제합니다.
- 출하·기타입고: 등록 시 사진과 판정 메모를 입력하거나, 목록의 **사진·이상 여부**에서 관리합니다.
- 발주입고: 목록의 **사진·이상 여부** 버튼으로 박스·품목 사진과 판정을 기록합니다.
- **미판정 / 이상 없음 / 이상 있음**은 사용자가 사진을 보고 직접 선택합니다. 판정 메모와 작성자가 함께 저장됩니다.
- 사진을 누르면 크게 볼 수 있으며 입고 자동 분석의 상세에서도 입고 사진·판정을 확인할 수 있습니다.
- 사진은 기록당 최대 10장, 서버 기준 장당 8MB입니다. 브라우저에서는 최대 1600px JPEG로 변환하여 전송합니다.
- 전체 백업에는 BOM, 생산일정 스냅샷, 모든 첨부 사진과 판정 기록이 포함됩니다.

## BOM 분류와 통합 입고목록

- BOM 품목에 **원자재 / 부자재 / 제품 / 상품** 분류를 지정합니다. 자재 행의 분류와 별도입니다.
- 원자재·부자재·상품은 구성자재 없이 입고용 품목으로 등록할 수 있습니다. 제품 BOM은 구성자재를 등록합니다.
- **물류 → 입고목록 → 발주입고**는 구매 발주목록을 불러와 입고 처리합니다.
- **물류 → 입고목록 → 기타입고**는 BOM에서 품목명·코드를 검색하고 품목을 선택한 후 수량·입고처 등을 입력합니다.
- 선택한 BOM의 품목명·분류·단위를 서버가 가져오며 등록 당시 정보를 저장합니다. 나중에 BOM을 수정해도 기존 입고 정보가 바뀌지 않습니다.
- 기존 BOM은 임의로 분류하지 않고 미분류로 유지합니다. 기타입고에서 새로 선택하려면 관리자가 분류를 지정해야 합니다.

모든 업무 입력 폼에 로그인한 입력자를 표시합니다. 수정 폼에서는 최초 입력자와 현재 작업자를 구분합니다.
발주·입고·세탁·의뢰·생산일정·출하·BOM의 목록에도 입력자를 표시하며,
발주입고에서는 최초 발주 입력자와 입고 처리자를 별도로 확인할 수 있습니다.
입력자는 서버의 로그인 세션에서 자동 기록합니다. 기존 기록의 최초 입력자를 수정자가 덮어쓰지 않습니다.
