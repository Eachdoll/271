# 서울세미텍 시스템

구매 · 품질 · 개발 · 생산 · 물류의 업무 흐름을 한 곳에서 입력하고 확인하는 사내 웹앱입니다.

- **운영 배포**: Codex Sites의 Cloudflare Workers + D1(DB) + R2(사진)를 사용합니다.
- **외부 패키지 없음**: 로컬 개발·테스트는 Node.js 22.13 이상과 내장 `node:sqlite`를 사용합니다.
- 로컬 데이터는 `data/app.db`와 `data/uploads/`, 운영 데이터는 영구 D1/R2에 저장됩니다.

## 실행

```bash
cd work-process-app
INVITE_CODE=local-test-code npm start  # http://localhost:3000
```

| 환경변수 | 기본값 | 설명 |
|---|---|---|
| `PORT` | `3000` | 서버 포트 |
| `DATA_DIR` | `./data` | DB·사진 저장 위치 (서버를 옮길 때 이 폴더만 백업) |
| `INVITE_CODE` | 없음 | **최초 가입 시** 초기 초대코드. 운영은 Sites 비밀 환경변수로 설정. 이후에는 관리자 화면에서 변경 |

테스트: `npm test`

## 가입 / 권한

- 가입: **이름 / 비밀번호 / 초대코드**로 신청 → 관리자 승인 → 로그인. 승인 대기·반려 상태에서는 업무 화면과 사진에 접근할 수 없습니다.
- 승인 기능 도입 전 계정은 승인 완료 상태로 유지하여 비밀번호·권한·기존 세션을 보존합니다.
- **처음 가입한 사람이 관리자**가 됩니다. 관리자는 `관리자 설정`에서
  - 가입 대기 목록 조회·승인·반려(사유 입력), 반려 시 기존 로그인 세션 종료
  - 초대코드 변경
  - 사용자별 담당 권한 지정: 구매 · 품질 · 개발(연구소) · 생산 · 물류, 관리자 지정
  - **품질책임자(승인권자) / 개발책임자(승인권자)**: 가입 승인된 사용자 행에서 해당 체크박스를 선택하면 즉시 저장됩니다. 해제하면 기존 로그인 상태에서도 승인 권한이 사라집니다. 책임자 지정 전에는 관리자가 의뢰 승인을 처리할 수 있습니다.
  - 비밀번호 초기화, 사용자 삭제

| 권한 | 할 수 있는 일 |
|---|---|
| 승인된 로그인 사용자 | 모든 목록 조회, 발주/세탁/일정/출하 입력, 분석·개발·샘플 **의뢰**, 발주입고 체크 |
| 품질 | 분석리스트 상태(대기/진행/완료) 변경 |
| 품질책임자(승인권자) | 분석의뢰 승인·반려 및 품질 업무 처리 |
| 개발(연구소) | 개발리스트 상태 변경 |
| 개발책임자(승인권자) | 개발의뢰 승인·반려 및 개발 업무 처리 |
| 생산 | 샘플의뢰 승인·반려, 샘플리스트 상태 변경, 다른 사람 생산일정 수정 |
| 구매 / 물류 | 다른 사람이 등록한 발주·세탁 / 출하 기록 수정·삭제 |
| 관리자 | 모든 권한 |

## 메뉴와 업무 흐름

| 부서 | 메뉴 | 내용 |
|---|---|---|
| 구매 | 발주목록 | 구매의뢰번호, 거래처, 품목명, 수량, 납기일. 물류 입고 상태가 색으로 표시됨 |
| 구매 | 세탁관리 | 입고일, (입고수량), 폐기수량, 불량폐기 사진 여러 장. 월별 폐기 합계·폐기율 |
| 품질 | 분석의뢰 | 의뢰요청서 ② 품질분석 양식. 접수대기 → 품질담당자 승인 시 접수번호 `Q-yymmdd-NN` 발급 |
| 품질 | 분석리스트 | 수입검사/의뢰검사/출하검사/공정검사 필터, 대기·진행·완료, 의뢰자 표시 |
| 개발 | 개발의뢰 | 타겟제품, 타겟단가, 사용용도, 사용량 등. 연구소담당자 승인 → `D-yymmdd-NN` |
| 개발 | 개발리스트 | 타겟제품, 타겟단가, 의뢰자, 대기·진행·완료 |
| 생산 | 샘플의뢰 / 샘플리스트 | 생산담당자 승인 → `S-yymmdd-NN`, 대기·진행·완료 |
| 생산 | 완제품 / 반제품 생산일정 | 일간·주간·월간 일정 입력(제품명, 수량), 일/주/월 달력 보기, 완료 체크 |
| 물류 | 입고목록 → 발주입고 | 발주목록에서 체크 → **입고확인(초록)** / **수량상이(빨강, 실입고 수량 입력)** / **확인중(노랑)**. 누구나 처리 가능, 처리자와 내용은 진행 코멘트에 자동 기록. 입고확인·수량상이 시 수입검사 자동 등록. 수량상이 항목에 **입고확인·완료**를 누르면 실입고 수량으로 **입고 종결**(나머지는 기타입고). 기록된 입고 수량 수정·입고 취소는 요청 후 **물류팀장 승인** 시 반영 |
| 물류 | 출하목록 | 출고일, 품목명, 수량, 거래처. 기본은 오늘 날짜, 기간 조회 가능 |

의뢰서는 상세 화면에서 **인쇄**할 수 있습니다.

## 배포

**[Codex Sites 배포·백업 안내](DEPLOY.md)**를 따릅니다.
운영은 D1과 R2를 사용하므로 Railway나 `/data` 볼륨을 설정할 필요가 없습니다.
관리자 설정에서 업무 기록과 사진을 포함한 전체 백업을 다운로드할 수 있습니다.

검증: `npm test` / 배포 산출물: `npm run build`.
로컬 테스트는 Worker 로직을 SQLite/R2 호환 어댑터로 실행하며 실제 Cloudflare 런타임 검증을 대체하지는 않습니다.

## 구매·물류 추가 항목

- 구매 발주: COA 요청 체크와 제품·상품·원자재·부자재 분류. 입고목록에서도 확인할 수 있습니다.
- 물류 기타입고: 발주 없는 입고를 분류별로 등록·조회·수정·삭제합니다.
- 물류 출하: LOT를 등록·수정하고 목록에서 확인합니다.
- 기타입고 수정·삭제는 등록자, 물류 담당자 또는 관리자에게 허용됩니다.

회사 로고는 [서울세미텍 공식 홈페이지](https://seoulsemi.com)에서 가져온 원본을 사용합니다.

## 입고와 분석리스트 연동

- **입고목록 → 발주입고 → 입고확인**: 분석리스트에 수입검사(대기)를 자동 등록합니다.
- **기타입고 등록**: 등록 즉시 분석리스트에 수입검사(대기)를 자동 등록합니다.
- 품목명·입고처·분류·입고수량·입고일·COA 요청 여부를 함께 넘기고 Q 접수번호를 발급합니다.
- 같은 입고의 반복 확인은 중복 등록하지 않으며 기존 분석의 진행/완료 상태와 결과를 유지합니다.
- 원본 입고를 나중에 수정·삭제해도 분석 이력은 최초 등록 스냅샷으로 남습니다.
- 품질 담당자가 분석 상태와 결과를 관리합니다. 기존 수동 의뢰는 승인 절차를 그대로 따릅니다.

## BOM으로 생산일정 등록

1. 관리자 계정으로 **관리 → BOM 관리 → 새 BOM 등록**을 엽니다.
2. 제품명·제품코드·완제품/반제품 구분·기준 생산수량·생산 단위를 입력합니다.
3. 자재별 이름·분류·기준수량당 사용량·단위를 추가하고 저장합니다.
   예: 제품 100EA 기준 원단 5kg이면, 생산 300EA의 원단 소요량은 15kg입니다.
4. **생산 → 완제품/반제품 생산일정 → BOM에서 가져오기**를 선택하고 생산수량을 입력합니다.
5. 소요량을 확인해 일정을 저장합니다. 일정의 **BOM·소요량** 버튼에서 등록 당시 기준을 볼 수 있습니다.

BOM 수정이나 사용 중지는 기존 생산일정의 제품·자재 기준을 바꾸지 않습니다.

## 사진 첨부와 입출고 이상 여부

- 개발·샘플 의뢰: 작성 화면에서 사진을 선택하고, 상세의 **사진 보기·첨부**에서 추가/유지/삭제합니다.
- 출하·기타입고: 등록 시 사진과 판정 메모를 입력하거나, 목록의 **사진·이상 여부**에서 관리합니다.
- 발주입고: 목록의 **사진·이상 여부** 버튼으로 박스·품목 사진과 판정을 기록합니다.
- **미판정 / 이상 없음 / 이상 있음**은 사용자가 사진을 보고 직접 선택합니다. 판정 메모와 작성자가 함께 저장됩니다.
- 사진을 누르면 크게 볼 수 있으며 입고 자동 분석의 상세에서도 입고 사진·판정을 확인할 수 있습니다.
- 사진은 기록당 최대 10장, 서버 기준 장당 8MB입니다. 브라우저에서는 최대 1600px JPEG로 변환하여 전송합니다.
- 전체 백업에는 BOM, 생산일정 스냅샷, 모든 첨부 사진과 판정 기록이 포함됩니다.

## BOM 분류와 통합 입고목록

- BOM 품목에 **원자재 / 부자재 / 제품 / 상품** 분류를 지정합니다. 자재 행의 분류와 별도입니다.
- 원자재·부자재·상품은 구성자재 없이 입고용 품목으로 등록할 수 있습니다. 제품 BOM은 구성자재를 등록합니다.
- **물류 → 입고목록 → 발주입고**는 구매 발주목록을 불러와 입고 처리합니다.
- **물류 → 입고목록 → 기타입고**는 BOM에서 품목명·코드를 검색하고 품목을 선택한 후 수량·입고처 등을 입력합니다.
- 선택한 BOM의 품목명·분류·단위를 서버가 가져오며 등록 당시 정보를 저장합니다. 나중에 BOM을 수정해도 기존 입고 정보가 바뀌지 않습니다.
- 기존 BOM은 임의로 분류하지 않고 미분류로 유지합니다. 기타입고에서 새로 선택하려면 관리자가 분류를 지정해야 합니다.

모든 업무 입력 폼에 로그인한 입력자를 표시합니다. 수정 폼에서는 최초 입력자와 현재 작업자를 구분합니다.
발주·입고·세탁·의뢰·생산일정·출하·BOM의 목록에도 입력자를 표시하며,
발주입고에서는 최초 발주 입력자와 입고 처리자를 별도로 확인할 수 있습니다.
입력자는 서버의 로그인 세션에서 자동 기록합니다. 기존 기록의 최초 입력자를 수정자가 덮어쓰지 않습니다.

## 일간·주간·월간 리포트

**홈 → 리포트·통계**에서 집계 단위와 조회 기간을 선택합니다.

- 분석의뢰 등록·현재 완료 추이, 현재 상태 분포와 완료율
- 발주입고·기타입고 수량, 이상 판정 건수
- 생산계획·완료 체크 수량과 상위 품목
- 출하수량, 단위·품목별 합계 및 기간별 상세 표
- 품목 분류·품목명·거래처 검색, 수량 차트 단위 선택
- 전체 단위 CSV 다운로드와 인쇄·PDF 저장

집계 기준:

- 주간은 월요일 시작입니다. 한국 날짜를 사용하며 데이터가 없는 기간도 0으로 표시합니다.
- 분석은 **선택 기간에 등록된 의뢰의 현재 상태**입니다. 완료 건수는 해당 기간 중 완료된 모든 건을 의미하지 않습니다.
- 발주입고는 입고확인·수량상이의 실제 입고수량을 사용합니다. 기타입고는 입력한 입고일·수량을 사용합니다.
- 생산은 일간·주간·월간 일정 중 하나를 선택하여 **일정 시작일 기준**으로 집계합니다. 완료 체크 수량은 완료 표시된 일정의 수량이며 별도 생산실적 입력값이 아닙니다.
- EA·kg 등 단위는 분리하며, 단위가 기록되지 않은 발주입고·출하·수기 일정은 **단위 미지정 + 품목명**으로 구분합니다.
- 출하와 분류 정보가 없는 과거 기록은 미분류에 포함됩니다.
- CSV에는 선택 기간·필터가 적용된 모든 단위와 집계일시·집계 기준을 포함합니다.

## 목록별 검색·필터

각 목록의 검색창에 입력하거나 **검색**을 누르면 조회합니다. **초기화**는 해당 화면의 기본 조건으로 돌아갑니다.
조회 건수와 합계는 현재 조건에 맞는 결과를 기준으로 표시합니다.

| 목록 | 검색·필터 |
|---|---|
| 발주목록 | 납기기간, 품목 분류, 입고 상태, COA 요청, 의뢰번호·거래처·품목·입력자·메모 검색 |
| 입고목록 → 발주입고 | 납기기간, 입고 상태, 분류, 검수 상태, 의뢰번호·거래처·품목·입력자·메모 검색 |
| 입고목록 → 기타입고 | 입고기간, 분류, 검수 상태, 품목·BOM 코드·입고처·입력자·메모 검색 |
| 세탁관리 | 조회월 또는 입고기간, 사진 유무, 메모·입력자 검색. 전체 기간 버튼 제공 |
| 분석·개발·샘플 접수대기 | 등록기간, 접수대기/반려, 품목·고객사·입력자·메모 검색. 분석은 검사 구분도 선택 |
| 분석·개발·샘플 리스트 | 등록기간, 진행 상태, 접수번호·품목·고객사·입력자·결과/메모 검색. 분석은 검사 구분도 선택 |
| 생산일정 | 달력의 날짜 범위, 완료 상태, 일/주/월 일정 기준, 제품·BOM 코드·메모·입력자 검색 |
| 출하목록 | 출고기간, 검수 상태, 품목·거래처·LOT·메모·입력자 검색 |
| BOM 관리 | 품목 분류, 사용/중지 상태, 품목명·코드·입력자·메모 검색 |
| 관리자 사용자 목록 | 이름 검색, 담당 권한/관리자 필터 |

의뢰 기간은 완료희망일이 아닌 **등록일**입니다. 발주·발주입고 기간은 **납기일**입니다.
생산일정 검색은 선택한 달력 범위와 겹치는 주간·월간 계획도 포함합니다.
검색어의 `%`, `_`는 일반 문자로 검색합니다. 날짜와 상태 조건이 잘못되면 안내를 표시합니다.

## 진행현황 코멘트

발주목록·발주입고·기타입고·분석/개발/샘플 의뢰 및 처리목록·생산일정·출하·세탁·BOM의 각 항목에서 **진행 코멘트**를 누르세요. 의뢰 상세 화면에서도 열 수 있습니다.

- 가입 승인 후 로그인한 직원은 코멘트를 조회하고 1~2,000자로 작성할 수 있습니다. 작성자와 한국 시간 기준 작성 시각은 서버가 기록합니다.
- 기존 진행상태·결과 메모와 별도로 누적되며, 발주목록과 발주입고는 같은 발주 건의 코멘트를 공유합니다. 담당자의 기존 승인·처리 권한은 그대로 적용됩니다.
- 새로고침으로 다른 직원의 코멘트를 확인하고, 이전 코멘트 더 보기로 50개씩 조회합니다. 저장 실패 시 입력 내용은 유지됩니다.
- 이력 보존을 위해 코멘트 수정·삭제는 제공하지 않습니다. 작성자 계정이 삭제되어도 작성 당시 이름은 보존합니다. 원본 업무가 삭제되면 화면에서 조회할 수 없지만 코멘트 데이터는 전체 백업에 보존됩니다.

## VOC 접수·처리

품질 메뉴의 **VOC 접수**에서 가입 승인된 로그인 사용자 누구나 고객사·제품명·수량·VOC 내용을 입력해 접수할 수 있습니다. LOT(미확인 시 빈칸), 단위·처리 희망일은 선택이며 사진은 최대 10장 첨부할 수 있습니다.

관리자 설정에서 **품질책임자(승인권자)**로 지정한 품질팀장이 접수대기 VOC를 승인·반려합니다. 관리자의 기존 승인 권한도 유지됩니다. 일반 품질 담당자는 승인할 수 없습니다. 승인 시 `V-날짜-번호`를 발급하고 **VOC 처리목록**에 대기 상태로 등록합니다. 품질 담당자·팀장은 대기 → 진행 → 완료 상태 및 처리 결과를 입력합니다.

접수·처리목록에서 고객사·제품·LOT·내용 검색과 등록기간 조회가 가능하며, 처리목록은 상태별 필터를 제공합니다. 항목을 누르면 상세·사진을 확인하고 **진행 코멘트**에서 직원 간 댓글을 남길 수 있습니다. 코멘트는 접수부터 완료까지 같은 항목에 누적됩니다. 반려된 본인 VOC를 수정하면 재접수됩니다.

VOC는 기존 requests의 type=voc, 수량·LOT·내용은 data에 저장합니다. 기존 업무 기록과 분리해 조회하며, 사진·코멘트는 기존 비공개 첨부/댓글 저장소와 관리자 전체 백업에 포함됩니다. 기존 DB 스키마 변경이나 기록 삭제는 필요하지 않습니다.

## 여러 품목을 한 번에 등록

발주·기타입고·출하·세탁·분석/개발/샘플/VOC 접수·완제품/반제품 생산일정에서 **여러 품목 한 번에 등록** 양식을 사용하세요.

1. 거래처·날짜·의뢰 내용 등 공통 정보를 한 번 입력합니다.
2. **＋ 품목 추가**를 눌러 품목명, 규격·사이즈, 수량, 단위, LOT를 품목별로 입력합니다. 예: 니트릴글러브 / S / 10 BOX, 라텍스글러브 / M / 20 BOX, PVC글러브 / S / 30 BOX.
3. 세탁은 원피스·투피스 등 옷 종류와 사이즈별 입고수량·폐기수량을 입력합니다. 기타입고는 각 행에서 활성 BOM을 선택하고, 생산계획은 BOM 선택 또는 직접 입력이 가능합니다.
4. **N품목 함께 등록**으로 최대 30품목을 한 번에 저장합니다. 같은 묶음 표시를 공유하지만 목록에서는 품목별로 표시하여 입고·승인·상태·댓글을 따로 관리합니다. 일부 품목만 먼저 입고되거나 분석이 완료될 수 있습니다. 기존 상세 양식은 ‘단일 품목 입력’ 안에 남아 있습니다.

공통 첨부 사진은 각 품목에 적용하며 품목별 사진은 저장 후 해당 항목에서 관리합니다. 품목 저장은 한 트랜잭션이며 잘못된 행이 있으면 전체 저장을 취소합니다. 등록 재시도는 같은 요청 번호로 중복 품목 생성을 방지합니다. 사진 저장에 실패하면 이미 저장한 품목을 다시 만들지 않고 사진 저장만 재시도합니다.

목록의 **규격·단위**에서 사이즈·단위·LOT를 정정할 수 있습니다. 본인 또는 해당 업무 담당자에게만 수정 권한이 있습니다. 입고 자동분석의 원본 스냅샷은 유지하고, 생산실적이 있는 일정의 품목·규격·단위·기간 변경은 제한합니다.

## 실제 생산량 점검

완제품·반제품 생산일정의 **생산실적 입력·조회**에서 실제 생산일·수량·메모를 입력합니다. 일정 등록자·생산 담당자·관리자가 입력하고 로그인 직원은 조회할 수 있습니다. 실적 입력일은 해당 일간·주간·월간 계획 기간 안에서 선택합니다.

- 여러 차례 생산한 수량은 같은 일정에 실적을 추가하여 누적합니다. 목록에서 계획수량, 실제 누적량과 달성률을 비교하고 상세에서 차이를 확인합니다.
- 기존 완료 체크는 실제 생산량으로 간주하지 않습니다. 기존 완료 일정에도 실적을 자동으로 채우지 않으며, 실적이 없으면 미입력으로 표시합니다.
- 입력한 실적을 고치거나 취소하려면 실적 창에서 **수정 요청** / **취소 요청**을 사유와 함께 올립니다. 지난 기간의 실적도 요청할 수 있습니다. **생산팀장(관리자 화면의 `생산팀장(실적 수정 승인)` 권한)** 이 승인하면 반영되고, 반려·철회하면 그대로 남습니다. 요청과 처리 이력은 모두 보존됩니다. 실적 이력이 있는 일정은 삭제할 수 없습니다.
- 실제 생산량 0도 입력할 수 있습니다. 오늘 이후 날짜의 실적은 입력·수정할 수 없습니다.
- 같은 생산실적을 일간·주간·월간 일정 여러 곳에 중복 입력하지 마세요. 리포트는 선택한 일정 기준 하나의 계획과 연결된 실적만 집계합니다.
- 리포트·차트·CSV에서 실제 생산량·계획 차이·달성률을 확인합니다. 생산 집계는 기존처럼 계획 시작일 기준이며 실제 작업 날짜별 입력 내역은 일정 실적 상세에서 확인합니다. 규격·사이즈와 단위가 다른 제품은 구분하여 집계합니다.

새 저장소는 기존 데이터에 컬럼과 item_batches/production_actuals 테이블만 추가하며 기존 기록·사진·권한을 보존합니다. 두 테이블과 취소 이력도 관리자 전체 백업에 포함됩니다.

## 재고 현황

**물류 → 재고 현황**은 따로 입력하는 화면이 아니라, 이미 등록한 기록에서 계산한 결과입니다.

`현재고 = 발주입고(입고완료·수량상이의 실입고) + 기타입고 + 생산실적 − 생산 투입(BOM 기준) − 출하 ± 재고 조정`

- **품목명과 단위가 같은 기록끼리** 합산합니다. 같은 품목은 발주·출하·생산에서 같은 이름과 단위로 입력하세요. 단위를 비우면 `단위 미지정` 줄로 따로 잡힙니다.
- 기본은 품목 합계이고 **규격·사이즈별** 보기로 바꿀 수 있습니다. BOM 자재에는 규격이 없어 생산 투입은 규격 없는 줄에 표시됩니다.
- 시스템 도입 전부터 있던 재고는 **기초재고**로 한 번 입력합니다. 실제로 세어 본 수량과 다르면 **실사**로 맞춥니다(차이만큼 조정 기록이 남습니다).
- 기초재고·실사·조정과 **안전재고** 기준은 물류팀장·관리자만 입력합니다. 모든 직원이 조회·내역 확인·CSV 저장을 할 수 있습니다.
- 현재고가 안전재고보다 적으면 `미달`, 0보다 작으면 빨간색으로 표시하고 대시보드에 품목 수를 알립니다. 음수는 입고·기초재고 누락이나 품목명·단위 불일치가 원인입니다.
- 기준일을 바꿔 과거 시점의 재고를 볼 수 있습니다. `0010_inventory.sql`은 조정·안전재고 표만 추가하며 기존 기록은 바꾸지 않습니다.

## 거래처 · 제품코드

- **구매 → 거래처 관리**: 누구나 거래처 이름·담당자·연락처를 등록하고 고칠 수 있습니다. 발주·입고·출하 입력에서 처음 쓰는 거래처 이름은 자동으로 목록에 추가됩니다.
- 발주 입력에서 거래처를 고르면 담당자·연락처와 함께 **최근 매입 품목**이 버튼으로 나타납니다. 누르면 품목·규격·단위·분류가 채워지고 수량만 입력하면 됩니다.
- 품목은 **제품코드로 불러오기**가 기본입니다. 목록에 없는 품목은 직접 입력할 수 있고, 이때 **임시 제품코드(TMP-0001 …)** 가 자동으로 붙습니다. 띄어쓰기만 다른 이름(니트릴글러브 / 니트릴 글러브)은 같은 품목으로 연결됩니다.
- 관리자는 **BOM 관리 → 코드 상태: 임시 코드만**에서 임시 품목을 **정식 코드로 확정**하거나 **기존 품목으로 합치기**를 합니다. 그 임시 코드로 등록된 발주·출하·기타입고의 품목명과 코드가 함께 바뀌어 재고가 한 줄로 합쳐집니다. 대시보드 '내가 처리할 일'에 정리할 건수가 표시됩니다.
- `0011_vendors_and_product_codes.sql`은 거래처 표와 코드 컬럼만 추가합니다. 이전 기록의 제품코드는 비어 있으며 자동으로 채우지 않습니다.

## 분류 · 샘플의뢰(상품) · 반제품 기록

- 품목 분류는 **원자재 / 부자재 / 반제품 / 제품 / 상품**입니다. 품목코드에는 **1차·2차·3차 분류**를 선택으로 지정할 수 있고, 재고 현황에서 분류·1차·2차로 걸러 볼 수 있습니다. 반제품은 기타입고로 받지 않습니다.
- **구매 → 샘플의뢰(상품) / 샘플리스트(상품)**: 누구나 의뢰하고 구매 담당자가 승인합니다(접수번호 `G-yymmdd-NN`). 생산의 샘플의뢰는 **샘플의뢰(제품)** 으로 이름만 바뀌었습니다.
- 발주의 **LOT는 선택**입니다. 모르면 비워 두고 입고 후 `규격·단위` 버튼으로 입력합니다.
- **생산 → 반제품 · 커팅/융착**: 라인별로 부직포와이퍼·천와이퍼·심리스 스무드·심리스 타키 생산량을 기록합니다.
- **생산 → 반제품 · 세탁(호기별)**: 세탁 호기마다 와이퍼/심리스글러브 세탁량을 기록합니다. (구매의 세탁관리는 세탁 입고분의 불량·폐기 기록입니다.)
- 두 화면의 **라인 관리 / 호기 관리**에서 생산 담당자·관리자가 라인(예: 1동 부직포라인, 2동 준크린룸)과 호기를 추가하고 이름을 바꾸거나 사용 중지합니다. 이름을 바꿔도 이전 기록에는 입력 당시 이름이 남습니다.
- 심리스글러브는 **사이즈(XS~XL)**, 와이퍼는 **규격(인치)** 을 함께 기록합니다. 커팅/융착은 필수, 세탁은 선택입니다. `사이즈·규격별로 보기`를 켜면 라인·품목·사이즈별 합계가 나옵니다.
- 기간 합계표는 라인(호기) × 품목으로 보여 주며 단위가 다른 수량은 합치지 않습니다. **커팅/융착 생산량은 재고 현황의 반제품 재고**(품목 + 사이즈·규격)로 잡힙니다. 세탁 기록은 재고에 넣지 않습니다. 같은 생산량을 반제품 생산일정의 실적에도 입력하면 이중으로 잡히니 한 곳에만 입력하세요.
- 기록마다 **양품수량**(필수)과 **불량수량·시작/종료 시각·생산인원**(선택)을 입력합니다. 양품과 불량은 따로 세며 총 수량 = 양품 + 불량입니다. 작업시간은 시작·종료 시각에서 자동 계산합니다. 재고에는 양품만 잡힙니다.
- 불량수량·시각·생산인원·LOT·비고는 입력자가 바로 고칠 수 있고, 양품수량·품목·사이즈·날짜·라인 변경과 삭제만 생산팀장 승인이 필요합니다.
- **리포트 · 통계**의 `반제품 생산` 구역에서 커팅/융착·세탁별로 품목별·라인(호기)별 **양품, 불량수량, 합계, 수율(양품÷합계), 불량률(불량÷합계), 작업시간, 인시당 양품**을 봅니다. CSV에도 포함됩니다.

## 반제품 계획·입력·불량 사유·수율 추이 (15.12)

- **반제품 생산일정은 계획만 입력합니다.** 실적은 `반제품 · 커팅/융착` 기록에서 자동으로 집계됩니다(같은 품목명, 계획에 사이즈가 있으면 같은 사이즈, 계획 기간 안의 작업일). 반제품 일정에는 실적을 직접 입력할 수 없으므로 같은 생산량이 재고에 두 번 잡히지 않습니다. 완제품 생산일정은 종전과 같습니다.
- 커팅/융착·세탁 입력은 **같은 날짜·라인(호기)의 여러 줄을 한 번에** 등록합니다. `＋ 줄 추가`는 앞줄의 품목과 단위를 이어받고, 한 줄이라도 잘못되면 전체가 저장되지 않습니다.
- 불량이 있으면 **불량 사유**를 고릅니다(커팅/융착: 오염·치수 불량·융착 불량·커팅 불량·찢어짐·구멍·이물·기타 / 세탁: 오염 잔류·손상·찢어짐·변색·이물·기타).
- **리포트 · 통계 → 반제품 생산**에 **수율 추이 그래프**(와이퍼·심리스글러브 선, 목표 수율 점선, 미달 구간 빨간 점)와 **불량 사유별 수량·비중**이 추가되었습니다. 목표 수율은 화면에서 바꿀 수 있고 그 기기에 저장됩니다.

## 반제품 품목(모델) 연결 (15.13)

- **BOM · 품목코드 관리**에서 반제품 품목을 등록할 때 **반제품 종류**(부직포와이퍼 / 천와이퍼 / 심리스 스무드 / 심리스 타키)를 지정합니다. 예) 부직포와이퍼: CF-707(6.5), CF-707(9) / 천와이퍼: NX-707, NX-808.
- 커팅/융착·세탁 입력에서 종류를 고르면 그 종류의 **품목(모델)** 목록이 나옵니다. 모델이 등록된 종류는 커팅/융착에서 모델 선택이 필수이고, 와이퍼는 모델을 고르면 인치 규격을 따로 넣지 않아도 됩니다.
- 재고 현황에는 **모델 이름**(예: CF-707(9))으로 반제품 재고가 잡히고, 반제품 생산일정도 같은 모델 이름으로 계획을 세우면 실적이 연결됩니다.
- 모델에 **구성자재**를 등록해 두면 (양품 + 불량) 수량만큼 원자재 재고가 자동으로 차감됩니다. 이미 입력한 기록은 입력 당시의 품목 정보를 유지합니다.

## 알림 · 편의 기능 (15.14)

- **대시보드 → 확인이 필요한 일**: 납기가 지난 미입고 발주, 완료 희망일이 지난 의뢰, 3일 넘게 대기 중인 승인, 최근 7일 수율 목표 미달 라인·호기, (관리자) 마지막 전체 백업이 7일 넘었을 때 알려 줍니다.
- **목표 수율**: 기본 목표(처음 95%)는 리포트 화면에서 생산팀장·관리자가 바꾸며 모두에게 적용됩니다. 라인·호기마다 다른 목표는 `라인 관리 / 호기 관리 → 이름·목표`에서 정합니다.
- **휴게시간(분)**: 시작·종료 시각과 함께 넣으면 작업시간에서 빠집니다(08:00~17:00, 휴게 60분 → 8시간).
- **최근 입력 불러오기**: 그 라인(호기)에 가장 최근에 입력한 날의 품목·사이즈·시각·인원을 그대로 불러오고 수량만 입력합니다.
- **세탁 대기**: 세탁 화면 위쪽에 품목·사이즈별 `커팅/융착 양품 − 세탁 처리` 수량이 나옵니다.
- **수정 이력**: 발주·출하·기타입고·생산일정을 고치면 무엇이 어떻게 바뀌었는지 진행 코멘트에 자동으로 남습니다.
- **발주·출하 입력은 다품목 양식 하나**로 합쳤습니다(1품목도 같은 양식). 단위 칸에는 yd·매·켤레 등 자동완성이 붙습니다.
- **백업**: 서버가 스스로 예약 백업을 하지는 않습니다. 관리자가 전체 백업을 내려받으면 날짜가 기록되고, 7일이 지나면 대시보드에 알림이 뜹니다.

### 세탁 검수·성적서 (15.15)

구매 → 세탁 검수·성적서에서 세탁 업체가 보낸 리스트를 세탁일별로 검수 입력하고, 누적 현황(수량·금액·사이즈별)과 생산/QC 세탁물 확인표를 인쇄·PDF로 발행한다. 단가는 화면의 「단가·설정」에서 입력한다. 마이그레이션 `0020_laundry_reports.sql`.

### 계정 추가 · 과거 세탁 기록 · 성적서 서명 (15.16)

관리자 설정에서 계정을 바로 만들 수 있다. 세탁 검수·성적서 화면에서 관리자는 변환된 과거 기록 파일(JSON)을 올려 누적에 넣을 수 있고, 구매 담당자는 「단가·설정」에서 확인자 서명 이미지를 등록해 발행하는 성적서에 자동으로 넣는다. 마이그레이션 `0021_laundry_report_signature.sql`.

### 버전 15.17: 입력 초안·조회 상태·승인 비교
- 발주 등 다품목 입력, 반제품 작업 기록, 세탁 검수의 입력 초안을 같은 브라우저 탭에 보관합니다. 화면을 다시 열어 **초안 복구**를 누르면 이어서 입력할 수 있습니다. 사진은 다시 첨부하세요. 탭을 닫거나 로그아웃하면 보관 상태가 사라질 수 있습니다.
- 검색 조건과 목록 위치, 생산일정의 날짜·보기 종류를 기억합니다. 공통 목록의 **초기화**는 저장된 조회 조건도 초기화합니다.
- 입고 수량·생산실적·반제품 변경은 **변경 전 / 승인 후**와 요청 사유·재고 영향 안내를 확인한 뒤 **승인하고 반영**합니다.

### 오퍼레이터 모드 · 버전 15.19
관리자 설정 → 가입 승인·사용자 권한에서 일반 사용자에게 **오퍼레이터(입력 전용)**를 선택하고, 해당 사용자가 새로고침하거나 다시 로그인하면 전용 화면이 열립니다. 기존 계정의 권한은 자동으로 변경되지 않습니다.

- **반제품 커팅/융착·세탁:** 작업일, 라인/호기, 종류·모델·규격, 양품·불량수량을 입력합니다. 작업시간·인원·LOT·비고는 추가 정보에서 펼칩니다. 여러 줄 입력과 초안 복구를 지원합니다.
- **완제품 실적:** 생산일에 해당하는 기존 계획을 골라 이번 생산량을 저장합니다. 계획은 생산 담당자가 미리 등록해야 합니다.
- 본인 입력 기록을 확인할 수 있으며 정정은 생산 담당자에게 요청합니다. 승인·삭제·계획 관리·다른 업무 화면은 서버에서도 제한됩니다.
- 오퍼레이터 역할은 일반 계정의 다른 업무 역할보다 우선합니다. 관리자 계정은 전체 권한을 유지합니다.

15.19에서는 확인창을 ×·Esc로 닫은 뒤 버튼이 잠기는 문제와 반제품 30줄 저장 뒤 입력칸이 없어지는 문제도 수정했습니다.

### 검사규격과 수입·출하 검사 이력 · 버전 15.20
1. **품질 → 검사규격 설정**에서 품질팀장(품질책임자) 또는 관리자가 검사 구분, 품목 카테고리, 품명·별칭, 항목·단위·하한/상한·측정 횟수를 등록합니다. 천와이퍼 흡수속도와 심리스글러브 박리강도 예시를 불러와 수정할 수 있습니다.
2. 등록된 품명/별칭·카테고리가 일치하는 새 검사의뢰에는 규격이 자동 적용됩니다. 발주입고·기타입고의 자동 수입검사도 포함됩니다. 출하검사는 분석의뢰에서 검사 구분을 출하검사로 선택합니다. 기존 의뢰나 규격이 없는 품목은 팀장이 검사 화면에서 규격을 적용합니다.
3. 품질팀원은 승인된 의뢰의 **검사규격·측정값**에서 LOT/시료별 수치를 입력합니다. 모든 값이 범위 안이면 합격, 하나라도 벗어나면 불합격, 이탈 없이 빈 칸이 있으면 검사 대기입니다. 평균은 참고값이며 0을 미입력으로 보지 않습니다. 판정된 기록의 수정은 사유와 이전 측정값을 보관합니다.
4. **품질 → 수입·출하 검사 이력**에서 원자재·상품 등 카테고리, 품명·별칭·LOT 검색, 판정과 의뢰기간을 조합해 조회합니다. 기존 데이터의 카테고리가 없으면 미분류로 표시합니다.

규격 변경은 새 의뢰부터 적용되며 과거 검사 기준은 유지됩니다. 기존 수기 검사 결과를 자동으로 합격/불합격으로 바꾸지 않습니다. 새 규격은 팀장이 저장해야 활성화됩니다.

15.21: 오퍼레이터 메뉴의 **수입·출하 검사 조회**에서 카테고리·품명·LOT 검색과 측정값·판정·수정이력을 읽을 수 있습니다. 측정값 수정과 규격 설정은 품질 담당 권한을 유지합니다. 대시보드는 재고 경고 조회만 실패해도 다른 현황을 표시하고 조회 실패를 안내합니다.

### 15.23 · 검사 항목 재사용과 세탁 입력
검사규격 설정에서 **저장된 검사 항목 불러오기**의 품목군·항목을 선택하면 항목명, 단위, 측정 횟수와 기준이 복사됩니다. 품질팀장은 항목 옆 **항목 보관함에 저장**으로 기준을 저장해 다른 규격에 재사용합니다. 미확정 기준은 먼저 입력해야 하며, 보관함 변경은 기존 검사규격과 과거 검사에 영향을 주지 않습니다.

세탁 화면은 **호기·제품코드·진행시각·수량**을 중심으로 입력합니다. 코드나 품명을 검색해 반제품 모델을 고르면 종류와 단위가 연결됩니다. 종료시각·휴게·인원을 새로 입력하지 않으며, 과거 기록의 상세 데이터는 보존합니다.

15.24: 커팅/융착도 제품코드·품명 검색으로 품목을 선택합니다. 규격·단위를 직접 입력하지 않으며 천와이퍼는 매, 심리스글러브는 켤레로 기록합니다. 시작·종료 시각만 입력하고 휴게·인원 입력은 생략합니다. 기존 기록의 상세 데이터는 보존합니다.

15.25: 세탁은 **세탁수량** 하나로 입력하며 양품·불량과 목표수율을 구분하지 않습니다. 호기별 일일 총수량과 가동 횟수를 표시합니다. 같은 호기·날짜·진행시각의 여러 제품 행은 한 번으로 계산합니다. 진행시각 없이 입력하면 한 번의 등록 묶음을 한 회로 셉니다. 단위가 다른 수량은 따로 합산하며 기존 세탁 기록은 전체 처리수량(과거 양품+불량)으로 표시합니다.
