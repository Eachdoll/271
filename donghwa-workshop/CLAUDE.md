## 편집 위치

- **루트 `dist/`는 편집하는 프런트엔드 소스입니다.** 일반적인 빌드 산출물로 취급해 삭제하거나 덮어쓰지 마세요. 빌드 도구 없이 ESM JavaScript로 실행합니다.
- `story-quality/src/`는 TypeScript 원본입니다. 수정 후 빌드하여 `story-quality/dist/`와 프런트엔드의 `dist/story-quality/` 사본을 동기화합니다. 루트 `npm run build`가 이 작업을 합니다.
- `server/cloud-api.js`는 계정별 D1/R2 보관 API입니다. `cloud-runtime/`는 Vinext/Cloudflare Worker 런타임이며 `db/schema.ts`와 `drizzle/`에 스키마·마이그레이션이 있습니다.
- `cloud-runtime/public/`, `cloud-runtime/dist/`, `.wrangler/`, `node_modules/`는 생성물이므로 직접 수정하지 않습니다.

Node.js 22.13 이상을 사용하세요. 컴파일된 패키지가 포함되어 있어 아래 테스트는 의존성 설치 없이 실행할 수 있습니다.

- 줄거리 품질 수정 호출(지적된 비트만 고치라는 1회 호출, 보급형 모델)의 결과는 **원래 줄거리를 기준으로** 다시 만듭니다(`mergeTargetedFix`): 지적된 비트에서는 `summary`·`newElement`·`failureReason`만 응답에서 채워진 값으로 가져오고, `settingKey`와 배경 행은 '중간 비트의 장소' 항목이 그 비트를 지적했고 값이 고른 배경 서랍 ID일 때만, `characters`는 선택한 등장인물 ID로 바꾼 뒤에만 가져옵니다. 항목이 이름을 댄 `plan.planted`·`plan.pattern`·`refrain`도 가져오고, 비트 index/type·`plotContract` 장부·그 밖의 필드는 줄거리 모델이 쓴 그대로 둡니다. 지적 안 된 곳의 변경은 버리고 `qualityMeta.untargetedFixRestored`(말버릇만이면 `catchphraseFixFallback`)에 남깁니다. 수정 호출은 **오류를 내지 않습니다**(2026-10-19): `{"outline":{…}}` 같은 감싼 응답은 풀고, 비트는 index로 맞추며(지적된 비트만 돌려준 응답·순서를 바꾼 응답), 앞뒤 설명이 붙은 JSON은 괄호 균형으로 읽습니다. 그래도 맞출 수 없으면(읽을 수 없음·잘림·index 없이 비트 수가 바뀜) 원래 줄거리를 그대로 쓰고 `untargetedFixRestored.mode: "original"`로 남기며, 남은 항목은 패키지 재검사가 참고 항목으로 돌립니다. 결정은 요청과 저장된 응답만으로 하므로 '다시 시도'는 새 호출 없이 같은 결과를 냅니다. 검사에서 멈춘(책이 없는) 작업에는 ③에 '줄거리 새로 만들기'(요금 확인 후 새 시드로 새 작업, 옛 작업은 보관)를 함께 보여 줍니다.

- R11 통합 검수: 가족 계정이 5GB를 넘으면(`quota_exceeded`) 클라이언트는 그 문구(`CLOUD_QUOTA_MESSAGE`)를 보여 주고 같은 책장 지문은 자동으로 다시 올리지 않으며, 책장이 바뀌거나 부모가 저장을 누르면 다시 시도합니다(용량 대기 중에도 `schedule()`은 막지 않아 바뀐 책장은 디바운스 저장이 스스로 한 번 다시 보내고, 읽기 기록만 바뀐 저장은 보내지 않습니다 — `tests/family-cloud-integration.test.mjs`). 서버는 선언된 `Content-Length`로 먼저 거절해 본문을 읽지 않습니다. `/auth/*`의 모든 오류 코드는 `family-auth.js`에 한국어 문구가 있어야 하고(`origin_forbidden` 포함), 라이브러리·미디어 요청의 401도 `reason: "family-session-expired"`를 유지합니다. 쉬운 만들기 화면에서 대화상자가 열려 있으면 브라우저 뒤로/앞으로는 아무것도 하지 않고 원래 항목으로 돌아가며, `discardDraft`는 `[data-modal-lock]` 대화상자(일회용 복구 코드)를 덮지 않습니다. 개인 클라우드 잠금이 걸리면 화면은 책장으로 가고, 편집 중 클라우드 불러오기는 책장으로 나간 뒤 확인합니다. 두 기기 가족 계정 흐름은 `scripts/r11-family-e2e.mjs`(실제 서버·메모리 D1/R2)와 `scripts/r11-family-scenarios.mjs`로 확인합니다.
- R12 펼침 구성: 새 K2~K4 초안 중 한글이 있는 책(`ko`·`bilingual`·`dual`)만 펼침 구성 책입니다(12쪽=펼침 6, 16쪽=펼침 8, 기본 16쪽, 비트 하나가 펼침 하나). 펼침 하나는 펼침면(`kind: "spread"`, 그림 2048x880) 한 장이거나 왼쪽·오른쪽 낱쪽(`kind: "page"`, 1536x1024) 두 장이며, 어느 쪽인지는 AI가 쪽 나누기에서 고르고 부모에게는 선택 이유(`cue`)만 보여 줍니다. `input.layoutPolicy`와 v4 펼침 규격(`specs.*.units`·`unitTolerance`)은 초안·FULL AUTO 작업을 만들 때 호출자(`startStoryWorkflow`·`createFullAutoJob`)가 `layoutFor(wizard)`로 한 번 정해 `inputFromWizard(..., {layout})`에 넘겨 고정합니다. `inputFromWizard`·재개·재접속·설정 변경은 다시 정하지 않습니다. K1, 영어만인 책, 기존 초안·작업·책은 R12 이전과 바이트 단위로 같아야 합니다(`tests/openings-legacy-r12.test.mjs` P0 고정값, `scripts/r12-legacy-dom.mjs --check`). 한글 분량은 펼침 단위 허용 범위(문장 수 −1~+2, 평균 어절 ±0.5, 긴 문장 1/3까지)로 검사하고 영어는 기존처럼 엄격합니다. 모델은 펼침 번호·`entryId`를 쓰지 않으며 앱이 `normalizeOpenings`로 매깁니다. 배치 필드(`LAYOUT_FIELDS`: kind·openingNo·side·entryId·cue)는 쪽 다시 쓰기·일관성 수정·스테이징에서 `copyLayoutFields`로 그대로 유지하고, 바뀐 응답은 거절합니다. 자동 수정은 책당 펼침 수의 2배(2×O)까지입니다. 그림이 하나라도 생긴 뒤에는 쪽 나누기 구조(펼침면/낱쪽, 쪽 나누기 다시 하기·나누기·합치기)를 바꾸지 않습니다. 기존 탭(R11 이전 앱)이 펼침 작업을 이어 실행하면 정책이 빠진 쪽 책이 되고 `layoutStatus`가 `layoutMismatch`로 표시합니다. `story-quality/` 패키지는 R12에서 고치지 않습니다. 기능 스위치는 `dist/book-layout.js` `OPENINGS_ENABLED`이고, 테스트·브라우저 점검은 불리언 `globalThis.__DONGHWA_R12_OPENINGS__`로 양방향 덮어씁니다.
- 새 DB 변경은 Drizzle 마이그레이션으로 추가합니다. 이미 적용한 SQL을 덮어쓰거나 요청 처리 중 DDL을 실행하지 않습니다.
- API 오류 때 샘플 그림·고정 이야기로 자동 대체하지 않습니다. 모의 테스트 통과와 실제 유료 모델의 글/그림 품질 평가는 구분합니다.
- 유료 `distill`, `eval`, 코치, 파인튜닝 실행은 사용자가 요청한 범위에서만 합니다. `topics:gen`과 `distill:estimate`는 모델 호출 없이 실행됩니다. 2026-10-17 증류 200편을 실행했고 승인본은 161편입니다. 원본·승인본·요약은 `story-quality/distill/runs/2026-10-17/`에 보존합니다. 앱에서의 증류 예시 사용은 R6-4의 명시적 옵션이며 기본 OFF입니다.

## 변경 전달

이 압축본은 Git 자격 증명·사용자 DB·실제 API 키를 포함하지 않습니다. 압축을 푼 뒤 자체 Git 저장소를 시작하고 기능별로 커밋하면 후속 통합이 쉽습니다. 기존 `.openai/hosting.json`의 프로젝트 ID는 현재 사이트의 식별자입니다. 소스 수정만으로 운영 사이트에 자동 배포되지 않으며 배포 권한과 호스팅 연결은 별도입니다.
