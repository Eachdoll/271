## 1. 무엇이 달라졌나

- **사용 기록 정리**: 사용 기록 한 줄은 토큰·요청 수·요금·모델·단계 같은 값과 1KB 이하의 작은 객체만 남깁니다. `*Checkpoint` 저널과 큰 보고는 남기지 않습니다. 재개에 쓰는 저널은 작업·초안 자체에 그대로 있습니다. 프로 초안의 단계 메타(`paginationMeta`·`sceneBriefsMeta`)에서도 저널과 승인 본문 복사본을 뺍니다.
- **기존 책장**: 앱을 열면 한 번 정리하고 저장합니다(실행 중이 아닌 완성 작업의 저널도 R27 규칙대로 정리). 책장의 '오래된 작업 기록 정리'도 같은 정리를 합니다. 클라우드로 보내는 사본도 보내기 전에 정리합니다.
- **상한**: 책장 글 자료는 R2 객체에 저장되므로 서버 `stateBytes` 8MB → **16MB**, `requestBytes` 10MB → **18MB**, 클라이언트도 16MB입니다. 넘치면 "클라우드에 저장하지 못했어요. 책장 글 자료가 n MB로 저장 한도 16.0MB를 넘었어요 (큰 곳: …)"와 정리 버튼 안내를 보입니다.
- 실측: 유료 K2 한 편(책+초안+작업) 442KB → 143KB, 회의 있는 K2 1,146KB → 270KB, K1 434KB → 156KB. Chromium 부팅 확인 508KB → 121KB(저널 0, 요청 수 그대로, 페이지 오류 0).

- **부모님 기기**: 앱을 새로 고침해 한 번 연 뒤(이때 책장이 정리·저장됨) 클라우드 창에서 '이 기기 자료 클라우드에 저장' → '이 내용으로 클라우드 저장'. 성공하면 클라우드 칸이 책 6권·캐릭터 8명·배경 12곳이 되는지. 실패하면 오류 줄의 문구를 그대로 보고합니다(크기와 '큰 곳'이 적혀 있음; 그림·키는 넣지 않음).
- 운영 서버의 상한: 16MB 미만(예: 10MB)의 합성 책장 JSON PUT이 `state_too_large` 없이 받아지고, 17MB는 `state_too_large`("16MB까지")로 거절되는지(격리 계정·테스트 데이터로만; 부모님 계정 금지).
- 격리 브라우저에서 저널 복사본이 든 합성 책장을 localStorage에 넣고 새로 고침하면 저장된 값이 줄어들고 `Checkpoint` 문자열이 사라지는지, 책·읽기·④가 그대로 열리는지.
- 기존 책 하나의 ④·읽기·인쇄가 예전과 같은지.
