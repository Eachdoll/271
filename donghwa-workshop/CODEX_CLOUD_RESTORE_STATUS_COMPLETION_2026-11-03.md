## 왜 비활성으로 보였나

부모님 화면은 기기 기본 샘플 4권·캐릭터 4명·배경 5곳과 클라우드 6권·8명·12곳을 보여 주면서 ‘클라우드 연결 확인 중’에 머물렀습니다.

1. 기존 앱은 **기본 샘플뿐인 기기**에서 클라우드 자료를 자동 복원합니다. 이때 busy가 끝날 때까지 불러오기·저장을 잠그는 것은 정상입니다. 그런데 파일을 내려받는 동안 phase를 checking으로 둬 실제 복원 중이라는 표시가 없었습니다.
2. **열린 창의 버튼은 렌더링할 때만 disabled를 계산했습니다.** 상태 구독은 문구만 바꾸므로 다운로드가 끝나 ‘클라우드 저장됨’이 돼도 불러오기 버튼은 회색 그대로일 수 있었습니다. 백그라운드 연결 확인 도중 창을 연 경우도 같습니다.

사이트 로그 표본의 미디어 GET 40건은 모두 HTTP 200이고, 일부 요청은 약 23.5초였습니다. 원본 그림·계정 자료는 열지 않았으며 로그에는 여러 방문자가 포함될 수 있으므로 이 수치로 부모님 PC의 복원 완료를 판정하지 않았습니다. 위 두 결함은 별도 합성 환경에서 재현했습니다.

## 바뀐 동작

- 자동/수동 복원 시작 시 syncing으로 바꾸고 **‘클라우드 자료 불러오는 중 · 그림·음원 x/y개’**를 표시합니다. 파일 개수는 SHA-256·크기 검사를 통과해 받은 수만 셉니다.
- 다운로드 뒤에는 **‘내려받은 클라우드 자료를 확인·저장 중’**을 표시합니다.
- 파일을 받고 기기에 반영하는 동안 버튼은 계속 잠깁니다. 완료·오류 후에는 busy와 진행 정보를 정리하고 같은 창의 버튼을 즉시 갱신합니다.
- 계정 인증 상태가 바뀐 열린 창의 로그인/자료 UI와 기기·클라우드 개수도 갱신합니다. 매 파일마다 전체 창을 다시 만들지 않아 초점을 빼앗지 않습니다.
- 복원 정책·저장 형식·계정 격리·무결성 검사·복구용 보관함·충돌 검사·부모 PIN·API 키 저장 방식은 그대로입니다.
