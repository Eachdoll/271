# 이야기 구성 알고리즘 점검과 재구성안 · 2026-11-03

부모님 요청: "스토리 플롯 구성을 원점부터 다시 짜 줘. 창의적이고, 등장인물이 다양하고, 재미있어야 해. 지금 봇들이 논의하는 구조가 이상적인가? 알고리즘부터 AI 창작 논리까지 다 점검해서 다시 짤지 개선할지 안을 모색해."

결론부터: **봇 구조는 이상적이지 않습니다.** 심사하는 봇은 넷인데 발상하는 봇은 하나이고, 그 하나도 9,500자 규칙 더미 위에서 씁니다. 다만 **전부 다시 짤 일은 아닙니다.** 뒷단(장면 디테일 → 비트별 작가 → 검사 → 쪽 나누기 → 그림)은 고정값과 검사기로 단단히 묶여 있고 잘 돌아갑니다. 바꿀 것은 **앞단(발상 → 회의 → 줄거리)** 이고, 그것은 새 표식 하나로 옛 초안을 건드리지 않고 통째로 갈아 끼울 수 있습니다.

## 1. 지금 구조 — 실측

### 1.1 흐름

```
재료(서랍 인물·장소·주제·카드 뽑기)
 → 기획 회의 (유료 5회: 성장 설계 → 작가 봇 피치 3개 → 편집자·그림 감독·독자 봇 심사 → 의장 점수 → 스토리 바이블)
 → 줄거리 1회 (8비트: setup → want → attempt×3 → turn → resolution → close)
 → 장면 디테일 1회 → 비트별 작가 (한글 8 + 영어 8) → 검사·수정 루프 → 쪽 나누기 → 통독 → 그림
```

### 1.3 회의

- 발상: 작가 봇 1회가 피치 3개(마음·모험·웃음 각도)를 씁니다. 세 피치는 **같은 전제**의 세 각도입니다.
- 심사: 편집자(12점: 뼈대·사다리·…)·그림 감독(8점: 그릴 수 있는 반전)·독자 봇(4점: "반전을 되말할 수 있나"). 의장이 가중 합산합니다.
- 독자 카드는 등급별 고정 문장입니다. 예: K2 반전 = "믿었던 것이 다른 것이었음", 웃음 = "실수·엉뚱한 추측·과장".
- 유료 5회 중 **발상은 1회**, 나머지 4회는 심사·정리입니다.

### 1.4 검사기

구조만 잽니다(비트 종류·시도 종류 중복·인과 연결·문장 수·어휘 등급). **재미는 아무도 재지 않습니다.** 모델 자기 보고는 믿지 않는다는 원칙은 옳지만, 그 결과 최적화 압력이 전부 '규칙 준수'로 갑니다.

## 2. 진단 — 왜 책이 서로 닮고 재미가 덜한가

1. **규칙 더미가 창작을 밀어냅니다.** "공식이 아니라 놀라움을"이라는 한 줄 아래 9,000자의 공식이 있습니다. 모델은 16개 블록을 **모두 만족시키는 가장 안전한 이야기**를 씁니다. 안전한 이야기는 서로 닮습니다. '뽀글머리'의 "숨어 있던 머리"는 이 압력이 만든 문장입니다.
2. **거시 구조가 하나뿐입니다.** 모든 책이 '바람 → 시도 셋 → 전환 → 끝'입니다. 이야기 모양 29종은 이 뼈대 위에 얹는 한 문단이라 뼈대를 바꾸지 못합니다. 실제 그림책의 큰 틀은 훨씬 다양합니다 — 누적(점점 쌓이다 와르르), 순환(처음으로 돌아오되 하나 다름), 묻고 답하기, 목록에 반전, 두 줄기가 만남, 독자에게 말 걸기, 되풀이 셋에 넷째가 뒤집기, 아는 사람은 독자뿐.
3. **창의성이 무작위 카드에 맡겨져 있습니다.** 발상·짜임·장치·끝 카드를 시드로 뽑아 붙입니다. 무작위는 다양성이지 창의성이 아닙니다. 카드끼리, 카드와 주제가 안 맞으면 모델이 억지로 풀로 붙입니다.
4. **회의는 발상이 아니라 심사입니다.** 넓게 던지고 이상한 것을 살리는 단계가 없습니다. 독자 봇의 기준 "반전을 되말할 수 있나"는 이해도이지 재미가 아닙니다. 5~6세가 "또 읽어 줘" 할 이유는 아무도 묻지 않습니다.
5. **인물이 서랍에 갇혀 있습니다.** R41로 4~5명이 나오게 했지만 전부 서랍 인물이라 책마다 같은 얼굴입니다. 책 한 권을 위한 인물(미용실의 앵무새, 자꾸 틀리는 배달 로봇)을 만드는 단계가 없습니다. 어른 인물의 바람·말투·결점도 없어서 엄마는 망토만 접고, 보라는 반말을 했습니다.
6. **그림 설계가 줄거리 호출에 섞여 있습니다.** 줄거리 모델이 pocket 위치·focus·backdrop·구도까지 정합니다(2,448자). 이야기를 짜는 호출이 조판을 하고 있습니다.
7. **웃음을 칸으로 요구했습니다.** 비트마다 humor 칸(R49로 선택으로 바꿈). 웃음은 설계에서 나와야지 칸에서 나오지 않습니다.

지킬 것도 분명합니다: 부모님 개입(R22 회의 결과 보고 진행), 저널 재생(유료 라운드 재사용), 독자 카드(연령 제약), 결정론적 검사기, R12 고정값, 에코 모드, 뒷단 전체.

## 3. 세 가지 안

### A안 · 보수 개선

- 줄거리 규칙을 2,500자 이하 '공방 브리프'로 압축(겹치는 문장 합치기, 예시 삭제).
- 그림 설계 블록(PICTURE PLAN 셋·pocket, 2,448자)을 줄거리 뒤 별도 호출로 분리.
- 회의의 피치 3개를 같은 전제의 세 각도가 아니라 **세 전제**로.

효과: 프롬프트 절반, 책 다양성 소폭 개선. 한계: 뼈대 하나·발상 1회·서랍 인물은 그대로. 비용 변화 없음. 2라운드면 됩니다.

### B안 · 앞단 재구성 (권장)

뒷단은 그대로 두고, **발상 → 회의 → 줄거리**를 '이야기 설계실 v2'로 바꿉니다. 새 표식 `storyEngine {version: 1}`이 붙은 초안만 새 길을 가고, 옛 초안·고정값은 바이트 그대로입니다.

**(1) 엔진 목록 — 뼈대를 여러 개로.** 지금의 '바람-시도-전환'은 엔진 하나가 됩니다. 처음 10개:

| 엔진 | 한 줄 | 아이가 기다리는 것 |
| --- | --- | --- |
| 바람-시도-전환 | 지금 구조 | 될까 안 될까 |
| 누적 | 하나씩 쌓이다 넷째에 와르르 | "또 하나 온다!" |
| 되풀이 셋·넷째 뒤집기 | 같은 일 셋, 넷째가 거꾸로 | 넷째 쪽 넘기기 |
| 독자만 아는 비밀 | 주인공은 모르고 아이는 안다 | "뒤에 있잖아!" |
| 역할 바꾸기 | 하루만 엄마가 아이, 아이가 엄마 | 어른이 틀리는 장면 |
| 바람표 앙상블 | 넷이 서로 다른 것을 바라 부딪친다 | 누가 양보하나 |
| 두 줄기 만남 | 왼쪽 쪽 A, 오른쪽 쪽 B, 끝에 한 그림 | 만나는 쪽 |
| 틀린 짐작 | 소리·흔적의 정체를 자꾸 틀린다 | 진짜 정체 |
| 묻고 답하기 | 이야기꾼이 아이에게 묻는다 | 내가 답하기 |
| 시간 제한 | 해 지기 전에·버스 오기 전에 | 마지막 한 번 |

엔진마다 비트 종류와 검사 규칙을 따로 둡니다(누적형은 '시도 종류 서로 다름'을 요구하지 않고 '쌓이는 수가 늘어남'을 요구). 24종 이야기 모양은 엔진의 하위 변형으로 정리합니다.

**(2) 발상 폭발 1회 (싼 모델).** 재료·주제·독자 카드·최근 책 기록을 주고 **전제 12개**를 받습니다. 전제마다: 엔진, 한 줄 줄거리, **가장 큰 웃음 한 장면**, **아이가 보고 싶어 할 그림 한 장**, 인물표(서랍 인물 + **책 한 권용 새 인물 최대 2명**, 각자 바람·결점·말투·존댓말 여부). 규칙은 금지 몇 줄뿐("최근 책의 엔진·웃음·소품을 쓰지 않는다, 등급 카드의 두려움 금지 목록").

**(3) 거르기 — 결정론 먼저, 봇 다음.** 최근 책 6권과 엔진·새 인물·웃음 장면·소품을 대조해 겹치는 전제를 뺍니다(코드, 무료). 남은 것 중 독자 봇 1회가 "다시 읽어 달라고 할 셋"을 고르되 기준은 **'기다리게 하는 쪽이 있나'**(엔진 표의 셋째 열)·'웃음 장면이 그림으로 보이나'·'새 인물이 할 일이 있나'. 부모님은 지금처럼 셋 중 고르거나 한마디를 보탭니다(R22 그대로).

**(4) 장면 먼저, 비트는 나중.** 고른 전제의 **세 장면**(큰 웃음·전환 그림·마지막 그림)을 먼저 씁니다(1회). 그다음 줄거리 호출은 "이 세 장면을 지나가는 비트 8개"를 씁니다. 작가가 그림을 향해 쓰게 됩니다. 지금은 비트를 쓴 뒤 그림을 찾습니다.

**(5) 줄거리 브리프 다이어트.** 줄거리 요청은 공방 브리프(≤2,000자: 인과·바람=걸림돌·말높임·웃음은 사건에서·마지막 비트는 행동) + 엔진의 비트 규칙(≤400자) + 설계 데이터(전제·세 장면·인물표). 그림 설계(picturePlan·pocket·focus·backdrop)는 줄거리 뒤 **별도 1회**로 옮깁니다.

**(6) 뒷단은 그대로.** 장면 디테일·비트별 작가·검사·쪽 나누기·그림·에코·인쇄는 손대지 않습니다. 작가 프롬프트에는 인물표의 말투·바람이 한 블록으로 들어갑니다(R49 말높임 줄은 인물표가 대신합니다).

유료 호출 수: 회의 5 + 줄거리 1 = 6 → 발상 1 + 독자 1 + 장면 1 + 줄거리 1 + 그림 설계 1 = **5**. 글자 수는 줄어듭니다(발상 요청이 큰 편이지만 싼 모델).

### C안 · 전면 재작성

비트 없이 '장면 흐름'으로 바로 쓰는 새 파이프라인. 검사기·쪽 나누기·그림 계획·에코·R12 고정값 전부가 비트에 묶여 있어 수개월의 회귀가 생깁니다. 재미가 는다는 보장도 없습니다. **권하지 않습니다.**

## 4. 재미를 어떻게 잴 것인가

자기 보고는 계속 믿지 않습니다. 대신:

- **다양성(무료, 결정론)**: 가족 책장 전체에서 엔진 분포, 책마다 새 인물 수, 웃음 장면 문장의 명사 겹침(자카드), 소품 재사용률, 같은 말꼬리 비율. `scripts/`에 리포트로 두고 라운드마다 돌립니다.
- **재미(유료, 승인 필요)**: R31b 방식의 A/B. 같은 주제 6개를 지금 길과 새 길로 글만 만들어(그림 없음) 부모님이 어느 쪽인지 모르고 읽고 "아이가 또 읽어 달라 할 것 같은 쪽"을 고릅니다. 유일한 재미 오라클은 아이와 부모님입니다. 비용은 글 전용 12권 — 실행 전에 추정치를 드리고 승인을 받습니다.
